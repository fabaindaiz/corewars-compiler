The carrier field for skipped spans records a span of the record that a harvest did not read. It must not be used for a span that was read with one source missing, such as the human's session transcripts on a machine that has none. A gap that stands for a missing source can never close where that source does not exist, so every later harvest re-reads the whole span. A missing source is recorded as such, in the harvest's report or in a field that names the source, and the frontier moves.

## Evidence

The home's own procedure, two carriers of one owner, one day. A harvest run from cloned copies read every commit, log and roadmap of two carriers, moved the frontier to that day, and also wrote the entire period as a gap, its commit message saying the span had been read without transcripts. A later harvest on another machine found no transcripts for either repository there either, so the gap could not close by reading them, and the whole period was read a second time. The method asks for a gap only where the human narrowed the period; it says nothing about a source that is missing.

What admission still needs: whether this use was intended (a deliberate marker for a machine that does have the transcripts), and a second occurrence.
